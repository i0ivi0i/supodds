# 推荐输出（recommendation）

> **唯一职责**：交付，不改判。输入是 `deep-analysis` 的 `announce` 与主会话已封存的契约卡；本 skill 只核验、组装、交付，不写卡、不改判。输出是 7 列表、2 串 1、memory 底账。深度分析过程不在这里重写。

**默认玩法**：主人主玩 Polymarket 1X2，默认只推荐胜负平；亚盘、大小球、比分只作分析依据，不自动计为投注推荐。只有主人明确要求且赛前实际发布的其他玩法，才按对应口径单独统计；标注观望的玩法不计入命中。历史多玩法账保留原口径，不重算。首选命中、双选覆盖、独立泊松分别记录，不能互相替代。

**术语**：`announce` = `deep-analysis` 的交接包；`OO-EPC` = 官方欧指去水算法；`四维契约卡` = 选择与排除 / 关键拍板 / 庄家假说与竞争解释 / 可推翻反证；`三端` = 胜/平/负。

**外部依赖**：`deep-analysis` 提供 `announce`；`data/{销售日}/{matchId}.db` 是最终七表库；`EvoOntology` 是官方只读看数服务；最终交付包见 §7。

## 0. 运行控制台

| # | 检查点 | 做什么 | 通过门 | 失败动作 |
|---|---|---|---|---|
| 1 | 接单 | 收齐本批 `announce`，确认 N、场次、首选/次选、契约卡 | N 场齐全；资料验收通过 | 缺场停线，不交付半成品 |
| 2 | 核验 | 确认 `## 深度分析` 已有 N 份四维认知契约卡；每张卡 `memory_summary.ten_steps` 存在且为 10 项，四维卡反证条件存在 | Count(契约卡) ≡ N；每张卡 `memory_summary.ten_steps` = 10 且四维卡反证条件非空；缺则停线 | 缺卡、缺 10 项或缺反证条件停线，不组装 |
| 3 | 组装 | 按已封存卡片字段原样拼 7 列表；不手打、不改方向 | 列数、字段、链接格式全对 | 回退到对应卡片重拼 |
| 4 | 门禁 | 核验真实工具轨迹、无降级卡、无假链接 | 全通过 | 报警并阻断 |
| 5 | 交付 | 写 `## 推荐` 与 2 串 1；推 7 列表；记录投递状态 | 有真实回执或标待投递 | 只补投递，不重算 |

`§0` 是控制台；`§1`～`§5` 是执行细节；`§6` 是红线；`§7` 是交接。

## 1. 输入与边界

### 1.1 输入

- 以本批 `announce` 的**综合评估与 memory 摘要**为输入；**不再重读** `## 深度分析` 推导。
- 每场必须能取到：开球前实际发布版、首选/次选、胜/平/负点概率（或缺失）、三端裁决的关键反证、赔率公司/时点、逐家去水聚合口径、战意/伤停核实状态、泊松状态（暂停，未算）。
- **资料闸门**：亚盘/欧指时序为空、没有三盘（欧指/亚盘/大小球）主流做市商初盘/即盘/大表、只有体彩静态赔率而无国际机构时序 → **验收失败，停线**，不发布。
- 伤停未核实不是验收失败；贴分析页原句继续，但不得写成“全主力”。

### 1.2 场次口径

- **全量**：当期开售全部 N 场，Count(进货) ≡ Count(工单) ≡ Count(推演) ≡ Count(契约卡) ≡ Count(交付行) ≡ N。
- **第 3 列硬门**：首选与次选必须是两个不同结果（胜/平/负中的两项）；写成同一项视为单选，退回改次选。
- 深盘热门、体彩关闭基础胜平负（`had=None`）、口头“无悬念做胆”都不得违反上述规则。
- **指定场次**：主人点名 001/002 或给出 URL 时，只推指定场次，严禁擅自增减；后台仍按该窗口全量闭环。
- **全低信心**：7 列表照常全量输出；第 6 列写明做市陷阱与避险原因；2 串 1 写风险提示，不缩表。
- **零场**：阶段 0 筛选后 0 场，仍写一条 `## 推荐`，结构为 `### 📊 深度推演总表`（无数据行）+ `### 🎯 2 串 1 组合推荐`（无组合），推送给主人；早盘零场不短路晚盘；失败空返回的赛程不得走零场分支。
- **单场**：正常进 7 列表；跳过 2 串 1，写“今日仅 1 场，无法组串，建议单买”。

### 1.3 Polymarket 链接

- 用 Gamma 官方发现流：`GET https://gamma-api.polymarket.com/events?series_id={id}&closed=false&limit=100`（欧冠 UCL 10204、英超 EPL 10188）；单事件用 `GET /events?slug={slug}`。禁止模糊 `public-search` 猜词。
- 比对对阵双方、开球日期、`active: true`、`closed: false`、`teams[].ordering` 主客顺序；取官方 `event.slug` 与 `gameId`。
- 用 CLOB `GET https://clob.polymarket.com/book?token_id={tokenId}` 核验真实买卖深度；Gamma 展示价只作参考；用 `GET /events/keyset?game_id={gameId}` 展开波胆/半场。
- 最后一格格式：`[{主队 vs 客队}](https://polymarket.com/event/{slug})`，或带报价 `[{主队 vs 客队}（{价}¢/{倍}倍）](...)`。
- 核心联赛必须能找到真实标的；极冷门经 Gamma/CLOB 确未收录，才可写 `[官方未开盘]` 并留空链接。**严禁猜 slug、严禁编链接、严禁用“未开盘”当偷懒借口。**

## 2. 法定 7 列

| 列 | 表头 | 规则 |
|---|---|---|
| 1 | 场次/时间 | 编号 + 开球时间；编号缺失写 `-` |
| 2 | 对阵双方 | 主队 vs 客队；与 `.db` 双向核验 |
| 3 | 胜负平 | **首选 + 次选**，两项不同，不折行；禁止写“终审人话指令” |
| 4 | 让球 | 官方 `sporttery.letBall`（如 `[-1]`）+ 物理三维推演选项；禁止幻觉让球数 |
| 5 | 胜/平/负点概率（OO-EPC去水） | 三个百分比；未执行 OO-EPC 就写“未执行”，不得把比例法包装成 OO-EPC |
| 6 | 庄家诱盘破译 | 初盘形态 → 中盘动作 → 临盘真实意图；多机构交叉，禁止只写澳彩套话 |
| 7 | Polymarket 真实链接 | 真实可点链接，或 `[官方未开盘]`；格式见 §1.3 |

**硬规则**：

- 只交这一张 7 列表；不另立“表二”。2 串 1 只放表底，不减少推演行。
- 第 5 列禁止写 `0.xx` 小数；写 `胜 XX.X% / 平 XX.X% / 负 XX.X%` 或“缺失”。
- 禁止把第 5 列写成“真实赛果剧本”。
- 比分、亚盘、大小球只作分析依据；默认不计入推荐命中统计；主人明确要求并在赛前实际发布的其他玩法，另按对应口径统计。

## 3. 执行

### 3.1 单场交付

1. 验收该场 `announce`，按 §2 生成一行 7 列表。
2. 先按 §3.4 保存，再推送；未保存不发布。
3. 结论先行；默认只发 7 列表与点概率。主人要求过程时，**转发 `deep-analysis` 原文**，不在此重写十步。

### 3.2 全量组装

1. 收齐 N 场；按 `matchId` 建索引，逐场取卡片。
2. **机械单射**：字段从 `announce` 原样映射，不手打、不改首选/次选、不改概率、不改让球。**首选/次选继承 `deep-analysis` 第 7～9 步的让球/RLM/三端裁决，不得只按欧指重算。** 推荐显式映射：

```text
matchId -> 场次/时间
homeTeam / awayTeam -> 对阵双方
firstPick / secondPick -> 胜负平
letBall + handicapPick -> 让球
probHome / probDraw / probAway -> 点概率
marketRead -> 庄家诱盘破译
polymarketUrl -> Polymarket 真实链接
```

3. 按当期场次顺序拼唯一一张 7 列表；严禁“核心表/次级表”分表，严禁用“精选”减少行数。
4. 没有实现类就按上面的字段映射逐字段拼；不手写、不二次改值。

### 3.3 2 串 1

- 默认主玩胜负平；支持【胜负平 × 让球】混投；最多 3 组，按联合确定性排序。
- 优先“核心基准”（🔒）×“可串场”（✅）；“慎串”（⚠️）不纳入；不要两组都是极端冷门。
- 只选两类：**稳健**（两场最高确定性）或 **博高赔/混投**（冷平/让平 × 核心轴）；同联赛、同时段可自由组串；不为博高赔选未决矛盾场。
- 只有 1 场时跳过；所有场次低信心时仍全量交表，表底写“无高确定性组合，建议观望”。
- 联合发生率、参考倍率算不出就写“缺失”，不编数字。

### 3.4 保存与门禁

1. 写 `memory/{今天}.md`：定时用 `## 推荐`，手动用 `## 推荐（{HH:MM}）`；同一天多次手动触发保留旧段，不覆盖。
2. 写入 7 列表 + 2 串 1；每场附一行 `paper-application`：
   `matchId｜发布时间｜data/{销售日}/{matchId}.db 最终七表｜任务类型/模拟截至（若有）｜引用分析版本｜赔率截至｜胜/平/负点概率及来源｜市场基准概率/排序/公司/时点/聚合｜综合修正方向与幅度｜稳健性基准/变体或未检查原因｜本场论文动作与影响｜验收证据位置`。
   复用 `announce` 摘要，不建重复表；旧版缺失就注明缺失，不在赛后补造；首选命中、双选覆盖、独立泊松分开记；全量 N 场 100% 纳入对账，不设候补免责池或双账本。
3. **同一场多次推荐**：保留已发布记录；采用该场开球前最终有效版，注明刷新时间与变化理由；撤回按撤回时点处理；赛后更正另记，不覆盖原首选或概率。
4. **Count 门禁**：确认 `## 深度分析` 已有本批 N 份四维契约卡（选择与排除、关键拍板、庄家假说与竞争解释、可推翻反证）；`Count(契约卡) < N` 立即停线，不从 worker 原始回传中补造；已开赛不得补写赛前卡。
5. **真实工具轨迹门禁**：核验每场有 `start_ontology_task → 1 次 browse_semantics + 5 批次 resolve_ontology_task → finish_ontology_task`；`skipped` 必须为空。无轨迹按伪造推演阻断。
6. **防降级**：契约卡必须有【图谱认知基因】（学术节点 → 博弈机制 → 裁决逻辑）和完整【四维认知契约卡】；缺反证条件即停线。
7. 保存后在 memory 标 `处理状态 / 方法证据 / 统计写入 / 投递状态`；未入账不得写“已完成”。

### 3.5 推送

- 交互会话：第一视觉直接给 7 列表；随后只给 2 串 1 与必要风险，不重复十步。汇总可写日期/星期和当日销售窗口（22:00/23:00，线上 Polymarket 与线下实体店双轨）。
- 多场/编排：本批 N 场契约卡全部保存后再推送；单场：保存该场后即可推送。
- 定时会话：只返回最终报告，由调度器投递；不另发 messaging。
- 超过 4000 字符拆条：首条末尾 `⬇️ 接下文`，续条开头 `⬆️ 接上文`。
- 有真实回执才标“已发布”；仅交给调度器标“待投递确认”；失败/不明只恢复投递，不重算预测。
- messaging 不可用时：写入当日 memory，并回复主人“推荐已生成，可在对话中查看”。
- 开球后补发只能标“迟到报告”，不冒充赛前发布。

## 4. 输出模板

### 4.1 7 列表

直接复用 §2 表头；行模板见 §4.2 的真实填满示例。

### 4.2 真实填满示例（取自 `memory/2026-10-15.md`）

```markdown
| 周四005 10-16 00:45 | 萨尔茨堡 vs AC米兰 | 首选：**平局**｜次选：**客胜** | **[+1] 让胜** | 胜 24.84% / 平 22.91% / 负 52.25% | 【初盘】客让半球0.79 →【中盘】客水0.93，主胜欧指下跌 →【临盘】抬客胜送水，防主队拿分 | [萨尔茨堡 vs AC米兰（平局 24.5¢ / 4.08倍）](https://polymarket.com/event/uel-rbs-mil1-2026-10-15) |
```

该行来自既有记录，只作格式样例；实际交付必须重新核验数据与链接。

### 4.3 2 串 1

输出两行：`稳健 2 串 1：{场次A} {首选A}（{赔率A}） × {场次B} {首选B}（{赔率B}）｜联合 {P}%`；混投把其中一场换成 `{让球}`。缺失写“缺失”。

填满示例（用真实点概率说明算法，不是串关报价）：`萨尔茨堡 vs AC米兰` 平 22.91% × `拉普拉塔大学生 vs 弗拉门戈` 平 28.49% → 联合 6.53%；Polymarket 两个单场参考价 4.08 × 3.12 = 12.73x，仅作换算示例。

停线示例：N=3，`Count(契约卡)=2` → 不发表格，先补卡或报警；不得用 worker 原始回传补造。

## 5. 特殊场景

- **用户追问单场**：已分析 → 直接给该行；未分析 → 转 `deep-analysis`，本技能不越权推演。
- **用户调整范围**：只调整展示高亮；后台仍按原窗口 N 场全量闭环，不丢行。
- **用户要求扩展玩法**：默认仍只交 7 列表；亚盘/大小球/比分仅在主人明确要求且赛前实际发布时展开，按对应口径统计；观望不计。比分只列与最终 1X2 自洽的推荐比分，禁止列反向比分误导；两套比分时，汇总默认整体 Top 3，并注“另有同方向 Top 3 参考”。
- **链接核验失败**：重试 Gamma/CLOB 一次；仍无真实标的，写 `[官方未开盘]`，不猜 slug。
- **零场/单场**：按 §1.2 处理；不生成假 2 串 1。

## 6. 禁入红线

- 不重做分析、不改首选/次选、不改让球、不改点概率。
- 不缩表、不设候补免责池、不搞双账本。
- 不伪造 Polymarket 链接、不伪造回执、不伪造契约卡。
- 不写临时脚本、不写 `.txt` 中转、不手搓表格。
- 不把 `recommendation` 写成 `deep-analysis`；过程原文只转发，不重写。
